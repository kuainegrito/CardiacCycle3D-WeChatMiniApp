# CardiacCycle 3D · 微信小程序

心动周期教学模型 [kuaiyu.site/cardiac_cycle](https://www.kuaiyu.site/cardiac_cycle/) 的微信小程序版。小程序直接运行网站本身的代码：生理模型、二维心脏、同步曲线和三维心脏都与网站同源，只外加一层小程序适配。

## 目录结构

| 路径 | 内容 | 来源 |
|---|---|---|
| `pages/lab/` | 唯一页面（布局按网站手机版重建） | 手写 |
| `engine/` | 网站的模型、二维心脏 `heart2d.js`、曲线 `charts.js` | `tools/sync-from-web.mjs` 复制，**勿手改** |
| `engine/mp-dom.js`、`engine/svg-canvas.js` | DOM 替身、SVG→canvas 绘制器 | 手写 |
| `data/` | 网站 `content/` 的 JSON 转成的 JS 模块 | `tools/sync-from-web.mjs` 生成，**勿手改** |
| `vendor/atlas3d.js`、`vendor/atlas-asset.js` | 网站三维心脏 + three.js 打包（入口 `tools/atlas-entry.js` 另含小程序用的 `parkAtlasView` / `resumeAtlasView`，并装入 `tools/fast-bounds.js`，见"性能处理"） | `tools/build-vendor.mjs` 生成，**勿手改** |
| `vendor/atlas-shim.js` | 三维心脏的浏览器替身 | 手写 |

三维心脏模型（约 2.3 MB）不在包里，打开小程序时即开始从 kuaiyu.site 下载（与二维心脏、曲线的初始化并行），并缓存在手机上；新版本模型保存时删除旧版本缓存。

## 从网站同步

网站仓库默认放在本目录的 `../../My_webpage/cycling-metabolism_simulator/apps/cardiac_cycle`；在别处时，把路径作为参数传给下面两个脚本。需要 Node.js 18+，网站目录里已执行过 `npm install`。

1. 同步模型、二维心脏、曲线和文案（网站 `content/`、`js/` 更新后执行）：

   ```bash
   node tools/sync-from-web.mjs
   ```

2. 重新打包三维心脏（网站三维相关代码或模型更新后执行）。先在网站目录执行 `npm run build`，脚本要从网站的 `dist/` 读取模型文件名：

   ```bash
   node tools/build-vendor.mjs
   ```

   模型文件名带哈希，网站重新部署后若模型变了，必须重跑这一步，否则小程序会下载旧地址而失败。

   打包后用 `node tools/check-chord-insertions.mjs` 核对三维包的腱索与网站逐位相同（2026-10-14 起三维包直接使用网站的腱索模块，不再替换）；`node tools/check-ectopy-bundle.mjs` 核对三维包里的期前收缩传导场（2026-10-23 起）。

3. 网站的改动还在分支上、没有并入网站 `master` 时，把该分支的工作树路径传给两个脚本；比较「复制的模块与网站相同」的测试用环境变量 `CARDIAC_WEB` 指向同一路径，例如 `CARDIAC_WEB=<路径> node --test tools/*.test.mjs`（不设时用默认的网站目录）。

同步时帮助文字里网站的小测提示句（「页面底部有小测，可检验理解。」及英文对应句）由 `tools/sync-from-web.mjs` 去掉，小程序没有小测（2026-10-20 曾手工删掉，2026-10-23 起改为每次同步自动去掉）。

## 编译与预览

1. 用微信开发者工具打开本目录（AppID 已在 `project.config.json`）。
2. 点「编译」。`vendor/` 已在 `project.config.json` 中排除 Babel 转译，`tools/` 不打包上传。
3. 开发阶段需在「详情 → 本地设置」勾选「不校验合法域名」，否则无法下载三维模型。
4. 模拟器里 canvas 会画在其他内容之上、也不受滚动区裁剪（开发者工具的已知差异）。重叠与三维效果请以「真机调试」或「预览」扫码为准。

## 心音播放

底部播放栏的「心音 / Heart sounds」开关默认关闭，手动开启后，S1、S2、S3、S4 和杂音按当前情景的模型时钟播放。暂停或拖动时间轴时停止；退出页面或切到后台时停止，返回后随播放恢复。倍速改变心音间隔，不改变音调。合成声音用于教学示意。

优先使用微信 `wx.createWebAudioContext`，不可用时改用 `wx.createInnerAudioContext` 播放包内 WAV，无需请求音频域名。本地 WAV 共约 31 KB，用 `node tools/build-heart-sounds.mjs` 可重新生成。设备静音/系统音量仍可能影响实际声音，应在真机上试听。

音频回归检查：`node --test tools/heart-audio.test.mjs`。

## 与网站的差异

- 异位刺激（2026-10-23）：没有快捷键 S、学习记录回放与 CSV 导出（小程序本来就没有这些）；刺激前不显示提示行（与网站手机版相同），按钮禁用时显示原因。
- 去掉了顶部标题与介绍、小测、临床联系、解剖结构选择栏（含色觉友好开关）、外链和行为统计；作者信息（姓名、邮箱、个人网站，点按复制）只在「?」帮助窗口底部。
- 「真实心脏」改称「三维心脏」；默认三维心脏（2026-10-10 起；载入失败时自动改用二维心脏）。三维心脏选中后始终固定在顶部（只有一块 WebGL 画布），在「时相与数值」页也保留。
- 二维心脏开启「固定心脏」时直接留在顶部，取消固定后随页面滚动；滚动本身不再切换或重建心脏画布。底部播放栏的「循环」旁有紧凑的「心音」开关，默认关闭。
- 点击心脏不再选中或高亮结构（二维、三维均是）；三维心脏单指旋转，双指缩放与平移。
- 「心腔壁不透明度」滑条在三维画面底部，与解剖 / 透视等预设联动。

## 性能处理

- 三维运动计算按实际耗时自动降频（每个 60 Hz 帧最多一次，慢手机上最多占四分之三的时间），播放与曲线保持流畅；拖动旋转时只渲染不变形，松手即恢复。三维运动只在帧循环里计算：滑块、按钮等操作先更新界面，下一帧再算三维心脏。
- 腱索（2026-10-13 起）：三维每步运动里，83 根腱索的计算原先占八成以上（无 JIT 时约 150 ms）。快速的腱索贴合（只算挂有腱索的 5 片房室瓣叶、每个姿势只算一次，先筛出插入点附近的三角形，法线与包围盒直接在数组上计算，结果逐位相同）先在小程序里做成，2026-10-14 起已并入网站（网站 CC-51），三维包直接使用网站的模块；`tools/fast-bounds.js` 让 three.js 其余几何体的包围盒 / 包围球也直接在数组上算。腱索在心室里：心室壁不透明（解剖视图）、镜头又在心脏外时看不见，这时既不计算也不绘制；换成半透明视图、拖动透明度滑块或把镜头推进心脏里时恢复，并在显示前先算到当前时刻。腱索末端贴合瓣叶的收窄（不到 1 毫米，占腱索计算的一半以上）只在镜头离心脏中心不到 0.6 个对角线时计算（2026-10-14 起；卵圆孔未闭的房间隔特写在此范围内），常规视图下腱索末端保持收窄前的形状。这两项判断都由网站三维心脏自己完成（`AtlasLabView.syncChords`）；小程序把 `chordSeating` 设为 `"near"`（网站默认 `"always"`，总是收窄），并在拖动镜头、换视图或透明度后请它重新判断（`pages/lab/lab.js` `syncChords`）。核对：`tools/check-chord-insertions.mjs`。
- 每拍相同的情景（14 个中 11 个，判断时比较第 0 拍与第 1–7 拍，差值小于 1e-9 视为相同）按第 0 拍计算，换拍时不重算。2026-10-14 前用严格相等比较：心率不是 75 次/分时，各拍的绝对时间带有约 1e-15 的舍入误差，相同的心拍被判为不同，每拍都重建曲线和三维表格（运动、心动过缓及任何改过心率的情景都会周期性卡顿）。
- 房颤、三度房室阻滞与卵圆孔未闭（每第四拍为 Valsalva 释放）的下一拍在本拍播放时分批预算：曲线的 400 个样本，以及新一拍的心房容积表（三维或二维心脏）和三维血流 / 充盈视图的流量积分要采的样本（模型暂存，`shareableSamples` 的 `shareBeat`），按本拍剩余的帧数分摊，每帧最多 8 ms；换拍时只用这些样本建表。
- 负荷滑块拖动时只更新数值，松手后重算一次；拖动时间轴时三维心脏按节流频率跟随，松手时精确定位。
- 切换情景（2026-10-13 起）：每个情景的模型只建一次并一直保留，三维和二维心脏按模型缓存的心房容积表、平均压和血流表在切回时直接复用；切换期间同一时刻的模型样本只算一次（75 次/分时曲线、心房容积表和平均压的采样时刻重合，三维血流层的净流量与两个房室瓣反流用同一网格）；最近 3 组曲线保留，切回情景或切换语言、左右心、复极 / 不应期显示时不重新采样。曲线、数值和二维心脏在点选时立即切换，三维心脏在下一帧只做一步运动计算；新视图编译着色器、准备教学图层期间三维心脏保持不动（最多 2 秒），不再在同一时刻重复整步计算；从血流 / 充盈视图切到其他视图时先换视图再计算，不为新情景白算血流表。
- 滚出可视区的曲线不绘制。
- 三维心脏只构建一次（2026-10-10 起）：
  - 在离屏 WebGL2 画布（`wx.createOffscreenCanvas`）上构建，构建期间不绘制也不编译着色器，所以切到二维心脏后构建照常进行；完成时若正显示二维心脏，心脏区右上角出现「三维心脏已载入 · 点此切换」，点一下即切换。
  - 从三维切到二维时，已建好的三维心脏「停放」（`parkAtlasView`：只释放渲染器、控制器等属于画布的部分，场景、模型、运动引擎、教学图层留在内存），切回时接到新画布（`resumeAtlasView`），保留视角与心腔壁不透明度；切回时不再显示载入卡片（2026-10-10 真机反馈：卡片会残留约 1 秒）。测试环境（CPU 降速 4 倍）中切回耗时由约 20 秒降到约 1–1.7 秒（主要是着色器编译）。
  - 手机内存告急（`wx.onMemoryWarning`）且正显示二维心脏时释放停放的三维心脏，之后切回会重新构建。
  - 不支持离屏 WebGL2、或离屏构建出错（网络以外的原因）时，改在页面画布上构建（原方式），此时切到二维心脏会放弃这次构建。
- 画布一律用 `wx:if` 创建 / 移除，不用 CSS 显示隐藏（微信中画布不服从 `display`、`z-index` 与滚动裁剪）；心脏固定时由滚动区外的停靠区显示。

- 原因：每次切换情景都新建模型对象。三维心脏（及二维心脏）按模型对象缓存的心房容积表、平均压（每次另建一个正常模型作参照）和血流 / 反流积分全部作废，一次切换重新采样模型约 1800–2900 次；三维心脏在点选时整步计算一次，视图换好后又在同一时刻整步计算一次；从血流视图切出时，还先为新情景算一遍随即隐藏的血流表。微信 iOS 小程序的 JS 不能 JIT，用 Node `--jitless` 模拟：切换一次 0.5–1.4 秒，其中点选后阻塞 0.35–0.8 秒。只换三维视图（解剖、透视、传导等）不换模型，所以不卡。
- 修正（只改 `pages/lab/lab.js`；未改网站、`engine/`、`vendor/`）：每个情景保留一个模型；切换期间共享同一时刻的样本；保留最近 3 组曲线和"每拍是否相同"的判断；三维心脏在下一帧只做一步，视图就绪前保持不动，并跳过视图对同一时刻的重算；离开血流 / 充盈视图时先换视图。详见"性能处理"。
- 效果（同一台电脑，Node `--jitless`，三维心脏）：点选后阻塞由 350–800 ms 降到 0–65 ms；切回看过的情景（如主动脉瓣狭窄 ↔ 正常）由约 650 ms、2900 次采样降到约 135–285 ms、3–5 次采样，剩下的主要是一步正常的三维运动；首次进入某情景约 920–1420 次采样（原 1800–2900 次），首次显示血流、传导视图或卵圆孔未闭时仍要建一次教学图层。二维心脏：每次切换约 240 ms，现首次 120–145 ms、切回约 1 ms。

### 2026-10-14：心率不是 75 次/分、改变速度时卡顿

- 反馈：正常情景 75 次/分已不卡；改速度（快慢都）卡；运动、心动过缓、房颤、三度房室阻滞等心率不是 75 的情景都卡。
- 原因（逐帧模拟播放，Node `--jitless`，实际页面与三维包）：
  - "每拍是否相同"用严格相等比较。心率不是 75 次/分时，各拍的绝对时间（拍号 × RR + t）带约 1e-15 的舍入误差，相同的心拍被判为不同：每拍都重建曲线，三维心脏也每拍重算心房容积表和血流 / 反流积分（约 1500 个模型样本），运动情景每拍卡约 300 ms，心动过缓约 220 ms；改过心率的任何情景同样。75 次/分时这些数值恰好精确，所以只有正常情景不卡。
  - 除正常（解剖视图）外，各情景都用半透明的教学视图，腱索看得见，仍要计算，其中末端收窄占一半以上：每步约 40 ms，播放只有 14–20 帧/秒，占用 72–91% 的时间。
  - 房颤、三度房室阻滞的心拍确实各不相同，换拍时三维心脏要现算新一拍的心房容积表（250–750 个样本），每拍卡 120–180 ms。
  - 改速度在逐帧模拟中不增加计算（正常情景任何速度每帧不到 3 ms）；上一轮加的每秒最多 30 步是唯一与速度有关的改动，快速播放时每步跨度大，可能显得不连贯。
- 修正（仍未改网站）：
  - "每拍是否相同"按 1e-9 容差比较（真实的差别在 0.1 以上）。
  - 腱索末端收窄只在镜头离心脏中心不到 0.6 个对角线时计算（卵圆孔未闭的房间隔特写在此范围内）；三维包导出 `setChords({ active, seat })`。
  - 心拍各不相同的情景，在本拍播放时预算新一拍的曲线和心房容积表 / 流量积分要采的样本（模型暂存），按本拍剩余帧数分摊，每帧最多 8 ms；换拍时只用它们建表。
  - 三维运动改为每个 60 Hz 帧最多一步（去掉每秒 30 步的上限）；系统时间往回调时三维心脏不再停住。
- 效果（Node `--jitless`，逐帧模拟 8–10 秒播放，最长一帧）：正常情景任何速度、或心率改为 50 / 150 次/分：60 帧/秒，不超过 3 ms。运动 304 → 34 ms，心动过缓 223 → 23 ms，房颤 677 → 25 ms，三度房室阻滞 191 → 23 ms，卵圆孔未闭 83 → 40 ms；半透明视图约 30–50 帧/秒（原 14–20）。仍不理想：房颤用 2 倍速时心拍间隔只有 0.25–0.4 秒，来不及预算，换拍时仍可能卡约 0.1 秒。
